Peeling → GE pipeline — full erasure sweep (0.00 → 0.45)

PPVH erasure decoder (arXiv:2208.01002). 2500 trials per erasure rate, fixed RNG seed so all conditions decode the identical samples. Full sweep across the code family's behavior, from the easy low-erasure regime through the threshold.

Pipeline under test: plain M=0 peeling, then a single global GF(2) Gaussian elimination over the residual Hz system (all remaining erased qubits at once) — no M=1, no M=2, no cluster-tree decomposition. The only optional step between peeling and GE is the DFS column reordering.
Baseline: the original paper decoder (full cascade — Peeling → VH → Cluster) with the only change being dense GE replaced by sparse GF(2) GE. The baseline uses no DFS.
GE time is elimination only; DFS reordering is measured separately and excluded from the GE-time chart. Times in milliseconds (GE/reorder are totals over all trials; decode time is the per-trial average).
Fill-in is measured directly (not inferred from time): total XOR element-writes counts the elements toggled by every GF(2) row-addition rows[idx] ^= pivot_set (the elimination work), and peak row-set size is the densest any row became during elimination. Comparing the no-DFS vs DFS fill-in curves on identical samples shows whether DFS actually reduces fill-in.
The baseline uses the seed-matched CASCADEFULL_ cascade data produced in the same run (identical samples; see the generator docstring).
