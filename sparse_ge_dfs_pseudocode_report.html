Sparse GF(2) Gaussian Elimination + DFS reordering

Pseudocode, design decisions, and a line-by-line map to the implementation — so you can verify the code matches what you intended. PPVH erasure decoder, arXiv:2208.01002.

1. Where this runs and what it solves

During decoding, after peeling (M=0,1,2) the remaining erasure is broken into clusters. Each cluster reduces to a small classical problem: given a binary parity-check matrix H, a syndrome vector s, and the set E of erased bit-columns, find a low-weight error vector e over GF(2) with H·e = s (mod 2), using only the erased columns.

utilities.py · perform_classical_syndrome_analysis_with_erasure(...) — the per-cluster chokepoint that dispatches to the backend.

Key idea. Represent each equation (matrix row) as a Python set of the column indices where it has a 1. Over GF(2), adding two rows is just the symmetric difference (XOR) of their sets. The syndrome is carried as one extra "augmented" column with the sentinel id aug = num_bits. Non-erased columns are never inserted (equivalent to zeroing them).

2. Plain Sparse GF(2) GE (the counterpart)

utilities.py · _sparse_solve_classical_syndrome_with_erasure(H, s, E, reorder=None)

# Inputs:  H (num_rows x num_bits), syndrome s, erased column set E, reorder flag
# Output:  minimum-weight e with H·e = s (mod 2), supported on erased columns

function SPARSE_GE_SOLVE(H, s, E, reorder):
    num_rows, num_bits = shape(H)
    aug = num_bits                       # sentinel column id for the syndrome
    erased = { c in E : 0 <= c < num_bits }

    # (1) Build augmented rows as SETS of column ids (only the 1-entries)
    for r in 0 .. num_rows-1:
        rows[r] = { c in erased : H[r][c] == 1 }
        if s[r] == 1:  rows[r].add(aug)

    # (2) Choose the order in which columns are tried as pivots
    if reorder == "dfs":
        col_order = DFS_ORDER(H, erased)        # timed separately (see §4)
    else:
        col_order = sort_ascending(erased)      # natural order = same result as dense
    candidates = col_order ++ [aug]             # aug is tried LAST

    # (3) Gauss-Jordan elimination over GF(2) using set XOR
    available = { 0 .. num_rows-1 }             # rows not yet used as a pivot
    pivots = [] ; pivot_row_of = {}
    for j in candidates:
        p = first index in `available` whose rows[p] contains j
        if p is None:  continue            # column j is a FREE variable
        if j == aug:   raise INCONSISTENT   # a "0 = 1" row -> no solution exists
        available.remove(p)
        for every other row q != p with j in rows[q]:
            rows[q] = rows[q] XOR rows[p]       # symmetric difference, in place
        pivot_row_of[j] = rows[p] ; pivots.append(j)

    # (4) Minimum-weight read-off: free vars = 0; each pivot var = its reduced syndrome bit
    e = zero_vector(num_bits)
    for j in pivots:
        if aug in pivot_row_of[j]:  e[j] = 1
    return e
Why this equals the original dense solver (when reorder=None). The reduced row echelon form of a matrix has a unique set of pivot columns and a unique reduced augmented column once the column-visitation order is fixed. With ascending column order, the sparse routine therefore selects the same pivots and reads off the identical minimum-weight solution as the dense Gauss-Jordan (standard_form). This was confirmed empirically: dense vs sparse give identical failure counts on every seeded trial.

3. DFS reordering (the new part)

utilities.py · dfs_order(H, E)

Build the bipartite Tanner subgraph induced by the erased columns and the check-rows that touch them. Two columns are neighbors when they share at least one check (row). DFS over this graph yields a column-visitation order, which is then used as the pivot-selection order in step (2) above. 

function DFS_ORDER(H, E):
    erased = sort_ascending({ c in E : 0 <= c < num_bits })

    # adjacency restricted to erased columns
    col_to_rows[c] = { r : H[r][c] == 1 }              for c in erased
    row_to_cols[r] = { c in erased : H[r][c] == 1 }

    visited = {} ; order = []
    for start in erased:                 # ascending starts -> also covers disconnected pieces
        if start in visited:  continue
        stack = [start]
        while stack not empty:
            c = stack.pop()
            if c in visited:  continue
            visited.add(c) ; order.append(c)
            neighbors = union( row_to_cols[r] for r in col_to_rows[c] )
            for nc in sort_descending(neighbors):   # push high->low so LOWEST index pops first
                if nc not in visited:  stack.push(nc)
    return order
Sparse GE + DFS is exactly SPARSE_GE_SOLVE with reorder="dfs": the only change is that step (2) uses the DFS column order instead of ascending order. Everything else (set-XOR elimination, free-variable handling, inconsistency check, min-weight read-off) is identical.
What DFS changes — and what it does not. A different column order changes which columns become pivots, hence which minimum-weight solution is returned (this can shift the logical-error outcome slightly). It does not change whether a solution exists, and it does not change correctness: every returned e still satisfies H·e = s.

4. Timing: reordering is excluded from GE time

utilities.py · perform_classical_syndrome_analysis_with_erasure(...) and SOLVER_STATS

function PERFORM_CLASSICAL_SOLVE(H, s, E):        # per-cluster chokepoint
    stats.ge_calls += 1
    backend, reorder = SOLVER_CONFIG
    reorder_before = stats.reorder_time
    t0 = now()
    try:
        e = SPARSE_GE_SOLVE(H,s,E,reorder)   if backend=="sparse"
            else DENSE_SOLVE(H,s,E,reorder)
    finally:
        elapsed = now() - t0
        this_reorder = stats.reorder_time - reorder_before
        stats.ge_time += (elapsed - this_reorder)   # <-- GE time EXCLUDES reordering
    assert (H·e mod 2) == s
    return e

# inside SPARSE_GE_SOLVE / DENSE_SOLVE, only the DFS_ORDER call is timed into reorder_time:
    t = now(); col_order = DFS_ORDER(...); stats.reorder_time += now() - t
So in every report: total_ge_time is the elimination time only; the DFS cost lives in the separate total_reorder_time and is subtracted out. That is exactly the "exclude reordering time" behavior used in the comparison graphs.

7. Verification checklist (does it match your intent?)

  • Rows stored as sets of 1-columns; GF(2) addition = symmetric difference (^=).
  • Syndrome carried as a sentinel column aug = num_bits, always tried last.
  • Only erased columns participate; non-erased columns are excluded (zeroed).
  • A column with no available 1-row is treated as a free variable (skipped).
  • A pivot landing on the augmented column means the system is inconsistent → raise (caller treats as "no solution").
  • Minimum-weight choice = all free variables set to 0; each pivot variable = its reduced augmented bit.
  • DFS = depth-first over the cluster's column graph (columns adjacent iff they share a check); neighbors pushed high→low so the lowest index is explored first; disconnected pieces covered by iterating ascending start columns.
  • Sparse + DFS differs from plain Sparse only in the pivot-column order; correctness is identical and guarded by the H·e==s check.
  • GE time excludes DFS reordering: only dfs_order is timed into reorder_time, which is subtracted from ge_time.
One thing worth confirming against your expectation: the minimum-weight read-off is the same heuristic as the original paper code — set all free variables to 0 rather than searching for the globally minimum-weight coset representative. If you intended a true minimum-weight search, that is a deliberate difference to flag.
